每日联网与离线录制协议 5

2026-10-08。手机连接相机热点后两端可能没有互联网，因此开始和停止录制不得依赖当次服务器请求。登录成功后后台同步账号、设备权限、套餐和待补报用量；每日同步失败不再阻止登录完成、进入首页或切换本地/远程模式，兼容尚未部署 syncDaily 接口的服务器。普通登录仍检查 token 和原有登录有效期。协议 5 的离线录制继续要求当天已成功同步的签名授权。跨日失败不会打断正在进行的录制，原截止时间继续生效。

身份与授权

旧协议的服务器序号是录制控制版本，用来隔离迟到的云端指令。新协议服务器提前签发绑定相机 SN、账号、日期、累计额度的 Ed25519 授权；App 转交原文和签名，只生成请求去重 UUID。相机验证签名，持久分配控制版本、任务 ID 和会话 ID，拒绝 App 自填版本/截止/会话，以及本地录制中的云端控制和提升版本的状态查询。停止仅携带当前任务和会话，由相机分配新版本，无需服务器。

设备/操作规则
默认固定相机（包括 2/3）录制V1 countType=1；累计分钟，use_count=floor(use_number/timeLength)，当前默认 120 分钟为一次。余额和套餐到期共同限制签名授权及相机截止。
1/4/6/7 录制保留原录制豁免，不扣 V1 录制套餐；单次仍最多两小时，授权仅当天可启动。
设备组组存在时按固定类型 3 计费；绑定物理相机时沿用物理 deviceId 选套餐，只有组而无物理设备的既有云端流程仍用 virtDeviceId。
直播countType=3 与录制分离；默认固定类型走 V1，6/7 走 V2 小时额度。直播需要联网，录制日授权不提供离线直播。

有限录制额度签发时被托管给对应物理相机，登录不扣次数。同一套餐不能同时被云端或另一台相机重复分配。停止后通过下次联网同步补报，相机累计计量水位和数据库扣量在同一事务更新，重复回执不重复收费。手机缓存删除、重新登录和跨日续签都不会重置相机累计额度。

剩余额度的云端可用性：日授权有效期间，已分配额度仍由本地相机持有。所有日授权截止已过后，先连接相机蓝牙读取空闲状态，再在两分钟内联网同步；服务器先结算遗漏用量，再归还未使用托管额度。没有新鲜相机状态时不会自动释放，避免旧离线授权仍可花费。旧回执在新日授权发出后仍可补报，但不会释放新授权持有额度。

计量与恢复

本地离线模式中，RabbitMQ 断线不会触发旧的 90 秒 Wi-Fi 自动连接、300 秒 4G 重置、450 秒相机重启。录制中、已接纳启动中，以及已激活日授权未到启动截止的空闲时间均受保护。日授权过期且空闲、或切回云端控制后，保留原云端网络恢复逻辑；已经启动的重启工作线程也会在重启前再次检查，并与本地启动互斥。

相机持久文件 record_control.offline 记录签名授权版本、累计分钟、请求和会话，按分钟预留；确认首帧后保留计量，从未录出首帧的失败启动退回预留分钟。持久写入失败则收紧截止并停止。进程/整机重启不清零，不接受旧授权版本回退。App 在蓝牙发起前写入用量队列，服务器补报失败保留队列并阻止新的离线录制授权同步。

本地无人值守时间窗

本地创建录制可选择开始时间、结束时间，并可清除恢复默认。点击开始录制时，空开始时间取该次点击的当前时间，空结束时间取开始时间后两小时。结束必须晚于开始；无人值守任务不接受已过结束时间。未开启无人值守时保留手动开始、手动停止行为。

无人值守先保存任务，再由手机前台服务启动录制，因此首次启动失败也可在窗口内重试。未来开始时间只等待，到开始时间查询相机状态并启动；窗口内每30秒查询，空闲且无启停命令执行时重试。到结束时间取消尚未完成的启动并发起停止，不等下一轮30秒检查；停止尚未确认或连接断开时保留任务并继续尝试，确认空闲后清除。正常停止录制或通知中的关闭无人值守均可取消任务。任务保留账号、环境与相机绑定，重启恢复不会在结束后重新开始。

离线协议5启动请求新增可选 record_until 毫秒截止，相机按 min(用户截止, 套餐截止) 分配实际 stop_at，并沿用持久化、单调时钟与已有截止守护。该字段只能缩短时间，不能扩大签名授权额度；迟到至用户截止后的启动直接拒绝。同一操作重试不延长已分配截止。要在手机断连后仍执行用户截止，需同步更新包含该字段的相机固件；旧固件依靠APP连接发起停止。开始与恢复仍要求有效日授权、可用套餐及相机连接。

部署与验收

顺序：部署有签名服务和新增数据库表的服务器，部署含公钥的协议 5 相机，再更新 App。三个接口为 POST /hm/competitionRecord/syncDaily、reportOffline、syncOfflineMeters，均使用现有账号认证和设备权限。服务自动创建 hm_offline_device_budget、hm_offline_recording_permit、hm_offline_quota_hold；生产数据库账号需允许 CREATE TABLE。新 App 要求相机协议 ≥5，旧相机提示升级。

服务器使用 Java 25 运行并支持 Ed25519；Spring 配置 hotme.offline-signing-key / 环境 HOTME_OFFLINE_SIGNING_KEY 指向 PKCS#8 PEM 私钥。部署样例见服务器 deploy/docker-compose.daily-offline.example.yml。密钥独立于代码仓库：目录 0700、私钥 0600、容器 UID 1000 可读、只读挂载。公钥在相机 record_control.h；新环境应生成独立密钥并同步公钥重新编译两份头文件。不要把私钥放入 Git 或测试报告。

验收命令：Android testRewooGztCrewDevDebugUnitTest；真实手机 Instrumentation DailyOfflineInstrumentation（正常安全停止，或 -e autoStop true 使用仅剩一分钟的专用测试套餐），MainTabRestoreInstrumentation；相机 tools/local_control_tests 的 signed daily、local control、reply bounds、status reporting；服务器 Maven hotme-admin 全量组件测试。实机测试专用相机 MAC/SN 位于测试源码，不应对生产录制执行。

验证边界

已在现有 Xiaomi 手机和一台 RK3588 相机实测，断开手机 Wi-Fi/移动数据、相机无 WAN。日期边界和时钟变动由单元测试覆盖，未等待真实午夜；不同品牌手机及大规模共享套餐并发尚未实机覆盖。当前用量上报沿用账号认证及设备授权，计量回执不是硬件签名的远程证明；离线启动许可本身经过服务器签名，相机控制版本绝不由 App 任意指定。
